## [2026-11-12] feat: звонки со звуком и групповые, вампирские темы Android (ADR-44)
- **Звук в узле** (`src/app/voice.rs`): Opus 16 кГц / 20 мс / 24 кбит/с с FEC; адаптивный джиттер-буфер 40–100 мс (джиттер
  RFC 3550 + углубление после опозданий с растяжением звука), восстановление по FEC и маскировка, смешивание собеседников;
  E-модель ITU-T G.107 → MOS. Зависимость `opus` (libopus; под Android собирается из исходников — `android/build_node.sh`).
- **Групповой звонок** до 5 участников, сетка «каждый с каждым» (`src/app/messenger/call_ops.rs`, вынесено из
  messenger.rs): ноги с общим id сеанса, встречные вызовы — остаётся нога от меньшего NodeID, уход участника не рвёт звонок.
- **CallReport** (kind 16) раз в 5 с: потери → избыточность FEC, круг по туннелю → RTT/2 для оценки качества (метки
  отправителя на разных устройствах дают расхождение часов, а не задержку).
- **API:** `/api/call/start?members=…`, `/api/calls` → `sessions`, `/api/call/audio` (локальный UDP-канал PCM с токеном),
  `/api/call/tone` (тестовый источник); `features.calls = true`, `group_calls`.
- **Android:** звонок из чата (личный и групповой), уведомление-вызов с полноэкранным режимом, экран звонка (говорящий,
  MOS, микрофон, динамик / у уха с датчиком приближения, свернуть), `CallService` (foreground с микрофоном), `CallAudio`
  (VOICE_COMMUNICATION, эхо- и шумоподавление); звонки в истории чата.
- **Android, темы «Кровавая луна» и «Ночь в замке»** (`ui/Decor.kt`, `ui/ThemePicker.kt`): стекающая кровь с падающими

  заголовки антиквой; выбор темы карточками с миниатюрами.
- **Desktop:** вкладка «Звонки» (позвонить контакту или группе, участники, качество, микрофон, недавние), полоса
  входящего звонка, 📞 в шапке чата; звук через `cpal` с передискретизацией (`desktop/src/voice.rs`).
- **Исправлено:** номер события в `/api/events` не рос без ожидающих клиентов (`watch::send` → `send_replace`) — клиенты
  пропускали события (уведомление о звонке не снималось; так же могли теряться сообщения и «печатает»); групповой звонок
  мог не установиться, если вызов участника приходил во время ответа инициатору.

  хэллоуинские темы и стикеры в хотелках).

## [2026-11-11] feat(android): Android-приложение — узел на телефоне, подключение к компьютеру
- `android/` — приложение на Kotlin + Jetpack Compose (Material 3, палитра desktop-клиента). Телефон — **полноправный узел**:
  `p2p-node` кросс-компилируется под `aarch64/x86_64-linux-android` (`android/build_node.sh`) и запускается
  foreground-сервисом; интерфейс работает через локальный HTTP API узла (ADR-34). Вкладки: Чаты (статусы APP_ACK/RTT,
  вложения), Файлы (выбор файла и «Поделиться» из других приложений, прогресс, открыть/переслать принятые), Сеть
  (пиры, туннели, Kademlia, профили relay), Узел (старт/стоп, **сканер QR** компьютера, `@псевдоним`, свой QR, настройки
  TLS/AKE/LAN, журнал). Уведомления о входящих, ссылки `p2p-overlay://` открывают приложение.
- Узел: `node.advertise_host` / `--advertise auto|IP` — адрес для пиров при `0.0.0.0` (раньше всегда `127.0.0.1`, недостижимый
  с другого устройства); `auto` выбирает частный адрес на Wi-Fi/Ethernet через `getifaddrs`, пропуская VPN/Docker.
  `/api/status` отдаёт ссылку-приглашение `link`. Тесты `tests/test_advertise.rs` (всего 141).
- Desktop: на вкладке «Подключение» — «Локальная сеть» (`--advertise auto`), «Ретрансляторы» (0–6 вспомогательных узлов
  рядом с основным: туннелю нужно ≥ 2 relay) и карточка **«Подключить телефон»** с QR.
- Проверено в эмуляторе Android 15 с 4 узлами на ПК: сообщения в обе стороны с APP_ACK, файл 1.18 МБ в обе стороны
  с совпавшим SHA-256. USERGUIDE §3–4, `android/README.md`, скриншоты `docs/img/android_*.png`, `desktop_phone.png`.

### fix(E1-6, E21-E22, E24-E26) — критические исправления RPC и идентичности

#### E1-6 / E24-E26 — Чтение пакетов в исходящих соединениях (`src/rpc/mod.rs`)
- **Проблема:** RpcClient отправлял запрос, но никто не читал ответ
  из TCP-потока — `pending.deliver()` никогда не вызывался, все RPC
  падали по тайм-ауту.
- **Решение:** функция `spawn_conn_reader(stream, pending)` запускает
  фоновую задачу чтения на каждое исходящее соединение.
  `ping()` и `find_node()` теперь принимают `SocketAddr`, сами вызывают
  `dial()` → `send()` → `spawn_conn_reader()`.

#### E22 — Проверка NodeID/pubkey при каждом входящем сообщении (`src/rpc/mod.rs`)
- `handle_ping`, `handle_find_node`, `handle_store`, `handle_find_value`
  вызывают `verify_node_id_bytes()` перед добавлением в routing table.
- Несовпадение `NodeID ≠ SHA-256(pubkey)` → `warn + bail!` + ERROR-кадр.

#### E21 — Тесты сохранности NodeID (`tests/test_identity.rs`)
- `e21_node_id_stable_across_restarts` — NodeID не меняется при restart
- `e21_different_dirs_different_ids` — разные dirs → разные ID
- `e22_verify_node_id_valid_pubkey` — корректный pubkey → true
- `e22_verify_node_id_wrong_pubkey_rejected` — чужой pubkey → false
