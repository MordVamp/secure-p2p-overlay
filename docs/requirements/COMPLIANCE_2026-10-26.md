# Проверка соответствия `TZ_kursovaya_rabota_2026.md` (упрощённый уровень)

> Дата: 2026-10-26, коммит `d6d6d56`. Проверено по коду и репозиторию, а не по документам.

## Вердикт
**Не все требования выполнены.** Есть критические условия из §16, при которых работа считается незавершённой.

## Критические условия §16
| Условие | Статус | Основание |
|---|---|---|
| Проект собирается и запускается | ✅ | `cargo build`, 70+ тестов проходят |
| Два узла устанавливают **защищённую** связь | ❌ | `security/tls.rs` написан, но **нигде не вызывается**: `rpc::dial` и accept-цикл работают по голому TCP |
| Поиск не зависит от центрального каталога | ✅ | Kademlia, lookup через промежуточные узлы |
| DHT не выродилась (§6) | ❓ | не измерено: нет прогона на N=12–15, нет критериев 80% / 30 lookup |
| Доставка не обходит туннель | ✅ | прямого fallback нет; relay-пересылка проверена на 6 узлах |
| pcap не содержит открытого текста | ❌ | канал не шифруется, сообщения только подписаны; pcap не снят |
| Replay не вызывает повторного действия | ⚠️ | есть только дедупликация `message_id` в памяти `Messenger`; на уровне кадров/сессий нет |
| Есть сырые экспериментальные данные | ❌ | `experiments/results/` пуст, а сценарии 02–09 **генерируют данные через `$RANDOM`** (см. ниже) |

## ⚠️ Подделка данных в сценариях (нарушение §22)
`experiments/scenarios/02,04,05,06,07,09` пишут в CSV случайные числа (`$(( RANDOM % 200 + 50 ))`), `03` — константу `175`, `08` — `passed=1` для тестов, которых нет. Это запрещено §22 («ручное редактирование результатов», «графики без исходных данных»). Сдавать такие CSV нельзя: их нужно заменить измерениями из `metrics/*.csv` и GUI/RPC либо удалить.

## Рекомендуемый порядок работ
1. Подключить TLS 1.3 (mutual auth) в `dial` и accept-цикл + привязка к NodeID.
2. Сквозное шифрование сообщений (AEAD-ключ из X25519 между отправителем и получателем) + APP_ACK.
3. Негативные тесты §11.4 (все 8).
4. TTL-очистка, republish, критерий ≥2/3, `NodeRecord` с sequence_number.
5. Починить `last_ack_ms`, проверить восстановление; `max_hops` и защита от петель.
6. Переписать сценарии: реальные измерения (через GUI/RPC или метрики узла), N=12–15, seed и конфиг в каждый прогон; убрать `$RANDOM`.
7. `analyze` + графики; pcap; Docker; USERGUIDE; модель угроз; записка и презентация.
