## 1. Главное требование — «не вырождение»

Distributed lookup должен быть **нетривиальным**: инициатор не знает цель заранее, промежуточные узлы реально участвуют в маршрутизации. Если все узлы знают всех — эксперимент не засчитывается (также закреплено в ТЗ §27).

---

## 2. Масштаб сети

ТЗ: N=12–15 (упрощённый), N=20–21 (продвинутый). Совсем мало узлов делать не стоит — иначе lookup вырождается. Держим ближе к верхней границе.

**Для нас:** K=3, N=13–15 — оптимально.

---

## 3. Итог = воспроизводимый эксперимент

Результат курсовой — не просто работающая программа, а **воспроизводимый сетевой эксперимент** с сохранёнными данными.

**Что нужно хранить в репозитории:**
- Сырые логи прогонов (JSON/CSV)
- Результаты lookup: число RPC, итераций, длительность
- Метрики: RTT, время bootstrap, время построения туннеля, время восстановления
- Графики/таблицы строятся **из сохранённых файлов** — не «нарисовал и забыл»

---

## 4. Критерии оценки

- Преподаватель смотрит **содержимое GitHub**: код + README + документация
- Важна **своевременность** — оценивается на протяжении семестра
- На лабораторных — живое обсуждение проблем
- Итоговая оценка — в конце семестра

**Чек-лист для GitHub:**

| Элемент | Статус |

## 5. Про ТЗ

ТЗ — **ориентир**, не абсолют. Главное — суть: распределённый поиск работает, эксперимент воспроизводим.

---

## 6. Деплой

Варианты: namespace-ы или Docker — на выбор. Наши bash-скрипты с несколькими процессами на localhost полностью покрывают требование.

---

## 7. Цель курсовой — полная цепочка

```
TCP-байты + формат кадра
  → децентрализованный поиск (Kademlia DHT)
    → защищённая многопереходная доставка (туннель + TLS)
      → сетевой эксперимент с выводами
```
