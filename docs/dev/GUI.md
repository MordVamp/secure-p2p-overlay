# GUI

Три интерфейса над одним и тем же локальным HTTP API узла:

| Интерфейс | Что это | Запуск |
|---|---|---|
| Панель узла | страница `node.html` во встроенном HTTP-сервере узла (`src/gui/http.rs`, без внешних зависимостей) | `p2p-node --gui-port 8001` |
| Оркестратор | `orch.html`: запуск/остановка кластера | `p2p-orchestrator --gui-port 8080` |
| Настольное приложение | `desktop/` — `p2p-desktop` на egui: чаты, контакты и псевдонимы, сеть, журнал; вкладки файлов и звонков (функции узла в плане) | `cargo run -p p2p-desktop [-- --profile NAME]` |

Приложение — отдельный пакет workspace (`cargo build` в корне его не собирает); с узлом общается только по HTTP
(`desktop/src/api.rs`, std без HTTP-библиотек), умеет само запускать `p2p-node` (`desktop/src/node_proc.rs`).
Что умеет узел, приложение узнаёт из `GET /api/status` → `features` и включает только поддержанные разделы.
Руководство и снимки экрана — [USERGUIDE §3](../../USERGUIDE.md#3-настольное-приложение-p2p-desktop).

## Панель узла
```bash
cargo run --bin p2p-node -- --port 7001 --gui-port 8001
# http://127.0.0.1:8001/
```
Статус и NodeID, таблица маршрутизации по бакетам, туннели, хранилище DHT; действия: PING, FIND_NODE, построить туннель, STORE/FIND (подписанные записи DHT с репликацией), отправка сообщений через туннель и список входящих (нужно ≥4 известных узла: 2 relay + получатель + отправитель).

## Оркестратор
```bash
cargo build --bins
cargo run --bin p2p-orchestrator -- --gui-port 8080
# http://127.0.0.1:8080/
```
Запуск N узлов (первый — seed, остальные bootstrap к нему), остановка одного/всех, ссылки на панели узлов (порт узла + 1000). Узлам передаётся только адрес seed (ТЗ §15.1).

## Флаги p2p-node
`--gui-port`, `--state-dir`, `--metrics-dir`, плюс прежние. Полный список эндпоинтов API — [USERGUIDE §5](../../USERGUIDE.md#5-веб-панель-и-http-api).
