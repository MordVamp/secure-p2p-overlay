## 5. Голосовые звонки — сделаны 11–12.11
Дискорд-подобный групповой звонок, 3–5 узлов, только LAN.
> 11.11: варианты транспорта, ограничения ТЗ и уточнённый план по шагам — [TRANSPORT_OPTIONS.md](TRANSPORT_OPTIONS.md).
> Главное изменение: медиа поверх туннелей вместо WebRTC; перед звуком — замер (шаг 0), пул соединений, ненадёжные медиакадры.
> **11.11: шаги 0 и 1 сделаны** — сценарий `media`, пул соединений `transport.reuse_connections` (ADR-39), результаты —
> [TRANSPORT_OPTIONS.md §7](TRANSPORT_OPTIONS.md).
> **11.11: шаги 2–4 сделаны** — TUNNEL_MEDIA, сигнализация CallOffer/Answer/Reject/Hangup, ключ звонка (ADR-43), сценарий
> `call`: установление 72 мс, кадр 0,6 мс (release) — [TRANSPORT_OPTIONS.md §7а](TRANSPORT_OPTIONS.md).
> **12.11: шаги 5–10 сделаны** — Opus, адаптивный буфер, FEC и маскировка, смешивание в узле; групповой звонок до 5
> «каждый с каждым»; звонки в Android (уведомление-вызов, экран звонка, CallService) и desktop (cpal); сценарий `voice`:
> 15/15, «рот — ухо» 68 мс, MOS 4,1 — [TRANSPORT_OPTIONS.md §7б](TRANSPORT_OPTIONS.md), ADR-44. Не проверено: два живых
> телефона в реальной Wi-Fi, звонки под netem (нужен root). Исходный план ниже — для истории.
1. **Дизайн-документ** (ADR): состав сессии, роли, модель угроз.
2. **Адресация**: DHT-запись `call:<id>` с подписанным составом участников (по аналогии с NodeRecord).
3. **Сигнализация** по защищённому каналу: `INVITE / ACCEPT / REJECT / BYE`, обмен медиаключами (ключ звонка шифруется E2E каждому участнику).
4. **Медиа**: WebRTC (crate `webrtc-rs`) либо упрощённо UDP + Opus (`opus`/`audiopus`) + SRTP-подобное AEAD; решение выбрать на этапе дизайна — WebRTC тяжелее, зато стандартно.
5. **Топология**: инициатор — временный SFU (звезда), пересылает потоки остальным; при отказе инициатора — завершение (или перевыбор — как расширение).
6. **Захват/воспроизведение звука**: `cpal`; для тестов — синтетический источник (тон/файл), чтобы метрики были воспроизводимы без микрофона.
7. **Метрики**: время установления, one-way latency, jitter, потери, поведение при отказе узла.
8. **Тесты**: отказ участника, чужой INVITE (неверная подпись), replay сигнала, переполнение jitter-буфера.
Оценка: 1–1.5 недели. Это расширение к этапу 8, а не замена обязательных пунктов.
