## 5. Голосовые звонки (после п. 2–4) — не начато
Дискорд-подобный групповой звонок, 3–5 узлов, только LAN.
1. **Дизайн-документ** (ADR): состав сессии, роли, модель угроз.
2. **Адресация**: DHT-запись `call:<id>` с подписанным составом участников (по аналогии с NodeRecord).
3. **Сигнализация** по защищённому каналу: `INVITE / ACCEPT / REJECT / BYE`, обмен медиаключами (ключ звонка шифруется E2E каждому участнику).
4. **Медиа**: WebRTC (crate `webrtc-rs`) либо упрощённо UDP + Opus (`opus`/`audiopus`) + SRTP-подобное AEAD; решение выбрать на этапе дизайна — WebRTC тяжелее, зато стандартно.
5. **Топология**: инициатор — временный SFU (звезда), пересылает потоки остальным; при отказе инициатора — завершение (или перевыбор — как расширение).
6. **Захват/воспроизведение звука**: `cpal`; для тестов — синтетический источник (тон/файл), чтобы метрики были воспроизводимы без микрофона.
7. **Метрики**: время установления, one-way latency, jitter, потери, поведение при отказе узла.
8. **Тесты**: отказ участника, чужой INVITE (неверная подпись), replay сигнала, переполнение jitter-буфера.
Оценка: 1–1.5 недели. Это расширение к этапу 8, а не замена обязательных пунктов.
