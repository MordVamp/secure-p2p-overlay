# Проектное решение

## Уровень реализации
**Упрощённый** — N=12–15, K_BUCKET_SIZE=3, min_relays=2, pool_size=1, TLS 1.3.

## Язык
**Rust 1.98+** с async/await (tokio). Обоснование:
- Строгая система типов исключает целый класс ошибок сетевого кода
- Нулевая стоимость абстракций → нет GC-пауз в сетевых операциях  
- `tokio` — промышленный async runtime с отличной TLS-интеграцией
- `ed25519-dalek`, `rustls` — аудированные крипто-библиотеки

## Сериализация
**MessagePack** (крейт `rmp-serde`). Сравнение с JSON:

| Критерий | JSON | MessagePack |
|----------|------|-------------|
| Размер бинарных полей (NodeID 32B) | base64 → 44 B | 33 B (raw bytes) |
| Скорость парсинга | умеренная | в 2–5× быстрее |
| Человекочитаемость | ✅ | ❌ (нужен hexdump) |
| Поддержка в Rust | serde_json | rmp-serde |
| Совместимость с MAX_FRAME_PAYLOAD | ✅ | ✅ |

**Выбор: MessagePack** — меньший overhead для бинарных NodeID и ключей.

## Криптография
- **Ed25519** (ed25519-dalek) — долговременная идентичность, подписи NodeRecord
- **TLS 1.3** (rustls + rcgen) — защита канала, упрощённый уровень
- **X25519 + HKDF + AES-256-GCM** — заложены в Cargo.toml под продвинутый AKE
- Собственная реализация примитивов **запрещена** (ТЗ §22)

## Обоснование N и K
N=13 (нечётное, удобно для кольцевого bootstrap).  
K_BUCKET_SIZE=3 → при N=13 таблица маршрутизации:
- log₂(13) ≈ 3.7 → ≈ 4 непустых bucket ожидается после сходимости
- Каждый bucket ≤ 3 контакта → суммарно ≤ 12 = N-1 ✓ (невырожденность)
