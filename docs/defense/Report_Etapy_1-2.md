> **Данные.** Приёмка: `experiments/results/accept_20261027_163001/` (N=13, коммит `4b35f86` — уже с TLS 1.3 и E2E),
> воспроизведение: `bash scripts/run_acceptance.sh 13 30`. Сценарии 01, 02, 05, 09 (ТЗ §15.1):

> воспроизведение: `bash experiments/run_all.sh`. Пилот без TLS (`accept_pilot`, коммит `a2b44fb`) оставлен для сравнения.

## 1. Язык и библиотеки
Rust 2021, tokio (async TCP), rmp-serde (MessagePack), ed25519-dalek, sha2, rustls (TLS 1.3), serde, tracing, clap, serde_json.
Узел, приёмка (`p2p-orchestrator acceptance`) и тесты — на Rust. Вспомогательные скрипты — Python 3: `scripts/scenarios.py`
только запускает процессы узлов и считает статистику по их HTTP API, `scripts/analyze.py` строит графики (matplotlib) из CSV.

## 2. Формат кадра
24-байтовый заголовок: `version`(1) `type`(1) `flags`(2) `request_id`(16, UUIDv4) `payload_length`(4, BE) + payload.
`MAX_FRAME_PAYLOAD = 65536` проверяется до выделения буфера. `FrameReader` — конечный автомат (частичные/склеенные чтения,
неверная версия/тип → ошибка без остановки процесса). Типы этапов 1–2: PING, PONG, FIND_NODE_REQUEST/RESPONSE, ERROR.
С этапа 3 кадры идут внутри TLS 1.3 (взаимная аутентификация, ключ сертификата = identity-ключ узла).

## 3. Сериализация
MessagePack: компактнее JSON (бинарные NodeID/ключи без base64), есть схема-в-коде через serde; Protobuf потребовал бы кодогенерации.
JSON оставлен для экспортов (routing tables, результаты).

## 4. NodeID
`NodeID = SHA-256(0x01 ‖ ed25519_pubkey)`. Ключ хранится в `NODE_STATE_DIR/identity.key`, поэтому ID стабилен при перезапуске (T2.1).
При получении контакта NodeID пересчитывается и сравнивается (T2.4; проверка в PING/FIND_NODE/PONG/контактах ответов).
Независимые тест-векторы: `docs/test_vectors/nodeid_xor.json` (сгенерированы Python hashlib, проверяются `tests/test_vectors.rs`).

## 5. k-bucket
256 bucket ёмкостью K=3, XOR-метрика (беззнаковое 256-бит BE), порядок LRU→MRU. Полный bucket: PING старейшего контакта —
жив → новый не добавляется (T2.8), мёртв → вытесняется (T2.9). Конфликт NodeID с другим ключом отклоняется (§18.3).

## 6. Bootstrap и lookup
Star: seed без bootstrap-контактов; остальные делают PING seed и self-lookup. Ring: узел i знает только узел i−1.
Итеративный lookup: α=3 параллельных FIND_NODE (first-K-wins), остановка при отсутствии прогресса, журнал опрошенных узлов
по итерациям, число RPC/итераций/длительность.

## 7. Результаты приёмки (`accept_20261027_163001`, N=13, K=3, star)
| Показатель | Значение |
|---|---|
| Критерии приёмки | 5/5 ✅ (сходимость, невырожденность, ≥95% lookup, lookup и FIND_VALUE после отказа bootstrap) |
| Сходимость (Δ суммы контактов ≤10% два окна подряд) | 17 011 мс — ≈ нижняя граница метода: запуск 13×300 мс + пауза 3 с + 2 окна по 5 с |
| Узлов с < N−1 контактами | 13/13 (критерий ≥80%) |
| Контактов в таблице (min / медиана / среднее / max) | 5 / 8 / 7.5 / 11 (N−1 = 12) |
| Lookup до отказа bootstrap | n=30; цель отсутствовала в таблице инициатора — 30; найдено 30; через промежуточный узел — 30 |
| Длительность lookup (min / медиана / среднее / max, p95) | 19 / 23.5 / 23.9 / 32 мс, p95 28 мс |
| RPC на lookup (min / медиана / среднее / max) | 4 / 5.5 / 5.1 / 8 |
| Итераций | 3 во всех 30 |
| Lookup после остановки bootstrap | n=10, найдено 10; длительность медиана 25 мс, max 38 мс; RPC медиана 5 |
| STORE / FIND_VALUE после отказа bootstrap | запись на 4 узлах (автор + 3 реплики), найдена |

**Сравнение с пилотом без TLS** (`accept_pilot`): медиана lookup выросла с 6 до 23.5 мс. Причина — на каждый RPC открывается
новое TCP+TLS 1.3-соединение с полным рукопожатием (решение ADR-01: соединение на запрос, без пула). RPC и итерации не изменились.

Графики и таблица: `experiments/results/accept_20261027_163001/plots/*.png`, `stats.md`.

## 10. Ограничения
- Все узлы на одной машине (localhost): задержки не включают сеть, только TLS-рукопожатия и обработку (debug-сборка).
- Сходимость в приёмке и в сценариях 01/09 измерена с точностью до окна опроса (5 с и 1 с); значения близки к нижним границам методов.
- Сравнение star/ring не выявило различий при N=12 — это результат, а не доказательство их эквивалентности.
- Сеть без потерь и задержек (netem не применялся).
